## 1. 整体架构

### 1.1 定位

`NewLife.Cube.React` 是第三代魔方（API 版 `NewLife.Cube`）的 React 前端皮肤 NuGet 包，独立仓库管理。用户引用 `NewLife.Cube` + `NewLife.Cube.React` 两个包，`dotnet run` 后浏览器打开即有完整管理后台。

### 1.2 分层总览

```mermaid

        SPA["React SPA（web/ 构建产物）<br/>React19 + AntD6 + Zustand + Vite"]
    end

    subgraph ".NET 宿主（用户工程，如 CubeDemo）"
        API["WebAPI Controllers<br/>（NewLife.Cube 核心：实体控制器/权限/菜单/字段元数据）"]
        SKIN["皮肤 DLL（NewLife.Cube.React）<br/>ReactService.UseReact + ReactModule"]
        EMBED["嵌入式 wwwroot<br/>（pnpm build → csproj EmbeddedResource → DLL）"]

    subgraph "公共包 @cube/*（monorepo，file: 本地引用）"

    SPA -->|"/api  axios"| API

    SPA --> P3
    SPA --> P4
```

### 1.3 层间关系与核心原则

- **后端（NewLife.Cube）**：负责认证、权限、菜单、字段元数据与 CRUD API——一切以字段元数据（`GetPage`）为驱动源
- **皮肤（本仓库 .NET 侧）**：只做"接入"——注册嵌入式静态资源 + SPA 回退，不承载业务
- **前端（web/）**：纯展示与交互，从 `@cube/*` 公共包读状态、调方法，`fieldControl.ts` 是字段→控件映射的单一真理源
- **公共包**：框架无关核心（axios 封装、认证/列表/表单业务逻辑、字段映射规则），Vue/React 双端共享

## 2. SKIN — 皮肤集成（.NET）

### 2.1 职责

| 职责 | 说明 |
|------|------|
| 嵌入式静态资源 | `pnpm build` 产物 `wwwroot/` 经 csproj `<EmbeddedResource>` 嵌入 DLL |
| 静态文件服务 | `UseReact` 用 `CubeEmbeddedFileProvider` 提供嵌入式文件，与主机 `WebRootFileProvider` 组合 |
| SPA 回退 | 未匹配 endpoint 回退 `index.html`，支持 Browser History |
| 模块注册 | `ReactModule : IModule` 供 `AddCube()` 自动发现 |
| NuGet 打包 | 版本/图标/描述/符号包配置齐全，依赖 `NewLife.Cube` NuGet |

### 2.2 核心组件

| 组件 | 所在工程 | 说明 |
|------|----------|------|
| `ReactService` | NewLife.Cube.React | `UseReact(env)` 扩展方法：装配文件提供器 + SPA 回退 |
| `ReactModule` | NewLife.Cube.React | `IModule` 实现，Module 模式注册静态文件 |
| `CubeEmbeddedFileProvider` | NewLife.Cube | 嵌入式资源文件提供器（`NewLife.Cube.React.wwwroot` 前缀） |
| `NewLife.Cube.React.csproj` | NewLife.Cube.React | `EmbeddedResource Include="wwwroot\**\*"` + `FrameworkReference Microsoft.AspNetCore.App` + `PackageReference NewLife.Cube` |
| `CubeDemo` | 示例工程 | `AddCube()` + `UseCube()` + `UseReact()` 完整调用链演示 |

### 2.4 打包与嵌入

```
web/（pnpm build）──► ../wwwroot/（Vite outDir）
                            │
                            ▼
NewLife.Cube.React.csproj  <EmbeddedResource Include="wwwroot\**\*">
                            │
                            ▼
NewLife.Cube.React.dll ──► NuGet 包（NewLife.Cube.React.{version}.nupkg）
```

- `vite.config.ts`：`build.outDir = '../wwwroot'`、`emptyOutDir: true`
- `.NET 侧`：csproj 嵌入 `wwwroot\**\*`；`ReactService.UseReact()` 注册嵌入式静态文件 + SPA 回退
- 部署只需 `NewLife.Cube.React.dll` + `NewLife.Cube.dll`，无物理 wwwroot 文件依赖

## 3. 公共包引用策略（关键决策）

### 3.1 当前方案：`file:` 本地引用 monorepo

| 项 | 内容 |
|----|------|
| 依赖声明 | `web/package.json`：`"@cube/api-core": "file:../../../NewLife.Cube/packages/api-core"`（5 包同理） |
| 内部依赖绕过 | `pnpm.overrides` 把 5 个 `@cube/*` 统一重定向到 `file:` 路径，绕过包内 `workspace:*` 在独立仓库无法解析的问题 |
| 构建脚本拦截 | `pnpm.onlyBuiltDependencies: ["esbuild"]`，忽略 `@cube/*` 的 `postinstall`（其 `dist/` 已由 monorepo 构建，无需重复构建） |
| 开发流程 | 改 monorepo 包源码 → 在 monorepo 跑 `pnpm build:packages`（或 `pnpm dev:packages` watch）重建 `dist/` → 皮肤（pnpm 下 `file:` = 符号链接）即时生效 |
| 前置条件 | 所有开发机需有 `../NewLife.Cube` monorepo 且已 `pnpm install`（保证各包 `dist/` 存在） |

**为什么可行**：团队所有成员都在本地开发 monorepo（Vue 成员也频繁改 packages），兄弟仓库路径稳定；`file:` 在 pnpm 下是符号链接，改动实时可见。

### 3.2 将来方案：npm 发布（`@newlifex/*` scope）

| 项 | 内容 |
|----|------|
| 包名 | `@newlifex/api-core` 等（org 自有 scope，比公开 `@cube` 安全） |
| 发布 | monorepo 增加 npm 发布 workflow（pnpm publish 自动把 `workspace:*` 改写为实际版本） |
| 皮肤引用 | `web/package.json` 的 `file:` → `^x.y.z` 版本引用，一行切换 |
| 迁移成本 | 仅 package.json + lockfile 变更，git diff 极小 |

### 3.3 设计决策表

| 决策 | 选项 | 选择 | 理由 |
|------|------|------|------|
| 公共包引用方式 | A. 复制进仓库 / B. npm 版本引用 / C. `file:` 本地引用 / D. git 依赖 | C（当前）+ B（将来） | 复制会产生双份代码分叉；npm 版本引用当前无发布权且包演进快；`file:` 契合团队"本地共改公共包"现状；包稳定后平滑迁移 B |
| `@cube/*` 内部 `workspace:*` | A. 改 monorepo 包 / B. 提交 file: 依赖 / C. `pnpm.overrides` 重定向 | C | 改 monorepo 会影响 Vue 开发；`overrides` 在皮肤侧独立解决，零侵入 monorepo |
| 皮肤依赖 NewLife.Cube | A. ProjectReference / B. PackageReference | B | 独立仓库不与 monorepo 源码耦合，引 NuGet 即可 |
| ASP.NET Core 引用 | 依赖传递 vs 显式 `FrameworkReference` | 显式 | NuGet 传递不可靠（实测缺失），显式声明更稳 |
| CI 自动化 | 立即改造 vs 暂缓 | 暂缓 | 依赖 npm 发布先落地；当前开发编译已可用，先解决当下 |

## 4. 前端架构（web/）

### 4.1 数据流（公共包 + zustand）

```
后端 API（/Auth /Cube /{type}）
   │  axios（@cube/api-core createCubeApi）
   ▼
stores/user（@cube/auth-logic/zustand）──► 登录/登出/用户信息/菜单/权限
stores/menu（树↔扁平 + 激活）
views/list（@cube/page-logic/zustand createPageStore）──► 字段/数据/CRUD/分页
   │  resolveWidgets（@cube/field-mapping）→ FieldMapping
   ▼
utils/fieldControl.ts（皮肤映射）→ ControlType/SearchControlType/ListControlType
   ▼
AntD 组件渲染（FieldControl 渲染器）
```

- **PageLogic（公共包）**：字段加载、列表查询、分页状态、CRUD、导入导出、图表——框架无关
- **fieldControl.ts（皮肤）**：把 FieldMapping 映射到皮肤控件类型——单一真理源，禁止在组件里写本地映射
- **组件只做渲染与交互**：不持有数据逻辑，从 store 读状态、调 store 方法

### 4.2 配置系统（对齐 Vue configure/）

```
优先级（低→高）：
  defaultConfig → env 配置（.env）→ window._CUBE_CONFIG_（运行时注入）
```

配置项：`base`（title/logo/footer）、`request`（baseUrl/timeout/附加头）、`auth`（tokenKey/登录页 URL）、`ui`（布局/主题）、`menu`（菜单字段映射）、`user`、`router`。

### 4.3 路由与菜单

- **静态路由表**（`router/index.tsx`）：`/`、`/login`、`/register`、`/activate`、`/forgot-password`、`/profile/security`、`/unauthorized`、`/loading`、`*` → `DefaultEntity`
- **DefaultEntity**：根据当前路径在菜单树中匹配，命中 → 渲染通用列表页，未命中 → 404
- **登录守卫**：RootLayout 检查 token，无 token 且路径需认证 → 重定向 `/login?r={redirect}`
- **特殊控制器页**：`views/db/DbPage`（/Admin/Db 数据库管理，非实体 CRUD）、`views/config/ConfigPage`（配置管理）

### 4.4 布局

```
RootLayout
  ├─ 未登录 → 渲染 Login 等公开页
  └─ 已登录 → 加载用户/菜单 → MainLayout
       MainLayout
       ├─ Sider：动态菜单（菜单树 → antd Menu，<lg 隐藏 + Drawer）
       ├─ Header：折叠按钮 + 单行面包屑 + NavbarSearch + 胶囊按钮(明暗/语言/通知) + 用户菜单
       ├─ Tabs：多标签页（stores/tabs，首页固定标签；仅剩首页时隐藏栏）
       ├─ Content：路由出口（内容容器 min(1440px,100%)）
       └─ Footer
```

### 4.5 字段控件映射（单一真理源）

对齐 Vue `fieldControl.ts` 的规则，皮肤内建三组映射：

| 映射 | 用途 | 输出类型 |
|------|------|----------|
| `resolveControl(field)` | 表单/编辑控件 | `ControlType` |
| `resolveSearchControl(field)` | 搜索控件 | `SearchControlType` |
| `resolveListControl(field)` | 列表单元格 | `ListControlType` |

**公共包分工**：`@cube/field-mapping` 提供框架无关的 `resolveWidget`（本工程扩展其支持 lovCode/lovMulti、json/icon/richHtml/richMarkdown/time/enum/Guid 等），皮肤 `fieldControl.ts` 在其基础上映射到 AntD 控件。

### 4.6 主题系统

- antd `ConfigProvider` + `theme.token` 驱动：**单一主题 × 明暗**（defaultAlgorithm/darkAlgorithm）
- `stores/theme`：当前明暗，持久化 localStorage
- `App.tsx` 同步 `body[data-cube-mode]` 驱动全局 CSS 设计令牌（`--cube-*`）

### 4.7 公共组件清单

| 组件 | 对齐 Vue | 说明 |
|------|----------|------|
| LovSelect / LovSelectTable | LovSelect/ | LOV 值集选择（dataSource 或 lookup API） |
| Uploader | Uploader.vue | 附件/图片上传（UploadFile） |
| RichEditor | RichEditor.vue | 富文本 html/markdown |
| JsonEditor / ColorPicker / IconSelector | 同款 | 专用输入 |
| UserMenu / UserAvatar / LogoutButton | 同款 | 用户区 |
| NavbarSearch | NavbarSearch.vue | 菜单搜索 |
| LanguageSwitch / ModeSwitcher | 同款 | 顶部切换器（单一主题收敛后无 ThemeSwitcher） |
| TabsView | TabsView.vue | 多标签 |
| NotificationBell | NotificationBell.vue | 通知（先确认后端接口） |

## 6. 构建与发布

### 6.1 本地开发

```bash
# 前置：本地有 ../NewLife.Cube monorepo（且已 pnpm install，保证 packages/dist 存在）

# 启动后端 API（CubeDemo，默认 http://localhost:5050）
dotnet run --project CubeDemo/CubeDemo.csproj

# 启动前端 dev（端口 5188，/api 与 /Ai 由 Vite 代理转发）
cd NewLife.Cube.React/web
pnpm install
pnpm dev
```

### 6.2 构建

```bash
cd NewLife.Cube.React/web
pnpm build        # 输出 ../wwwroot
pnpm type-check   # tsc 类型检查
pnpm test:unit    # Vitest 单测（136 个）
# .NET 侧（嵌入 wwwroot）
dotnet build 魔方React.slnx -c Release
```

### 6.3 发布（CI 规划中，⏸ 暂缓）

```
web pnpm build → wwwroot → dotnet build 魔方React.slnx → dotnet pack NewLife.Cube.React.csproj
   → 发布 nuget.org + GitHub Packages
```

当前 `.github/workflows/` 为旧仓库拷贝（引用 `魔方.sln`/`NewLife.Cube/*.csproj`），待公共包 npm 发布就绪后统一改造（见[功能清单](功能清单.md) §4 CI 模块）。
