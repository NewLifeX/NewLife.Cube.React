# NewLife.Cube.React 需求文档

> 版本：v1.1 | 日期：2026-10-24

本文档描述 `NewLife.Cube.React`（魔方第三代 WebAPI 前端的 React 皮肤）的愿景、核心目标和功能方向。完成状态在[功能清单](功能清单.md)中追踪，详细设计在[架构设计](架构设计.md)中展开。

---

## 1. 背景与愿景

### 1.1 系统定位

魔方（NewLife.Cube）是一个"数据驱动 + 快速迭代 + 可深度定制"的快速 Web 开发平台。第三代魔方采用前后端分离架构：后端 `NewLife.Cube` 提供 WebAPI 与字段元数据，前端皮肤提供开箱即用的管理后台界面。

`NewLife.Cube.React` 是第三代魔方的 **React 前端皮肤**，以独立 NuGet 包 + 独立 Git 仓库的形式交付。用户引用 `NewLife.Cube` + `NewLife.Cube.React` 两个包，`dotnet run` 后浏览器打开即有完整管理后台——登录、动态菜单、字段元数据驱动的列表/表单、CRUD、导入导出、AI 助手等，零前端开发。

各相关工程定位：

| 工程 | 定位 |
|------|------|
| NewLife.Cube（monorepo） | 后端核心（实体控制器、权限、菜单、字段元数据、WebAPI）+ 公共前端包仓库 |
| **NewLife.Cube.React（本仓库）** | React 系前端皮肤（React 19 + Ant Design 6 + Zustand + Vite） |
| NewLife.Cube.Vue | Vue 系前端皮肤（Vue3 + Element Plus + Pinia） |
| packages/@newlifex/* | 框架无关前端公共包（api-core / auth-logic / page-logic / field-mapping / page-utils），位于 monorepo，本仓库以 `file:` 本地引用 |

### 1.2 愿景

- **符合魔方皮肤设计规范**，成为 React 系皮肤对照规范的实现样板
- **全面消费公共包** `@newlifex/*`，验证并补齐公共包能力（回馈 monorepo，供 Vue 等皮肤共享）
- 构建产物嵌入 DLL，NuGet 引包即得完整前端，**零前端开发**
- 未来 React 系皮肤（Shadcn / MUI / Arco 等）可基于本仓库结构复用

## 3. 功能需求

### 3.1 SKIN — 皮肤集成（.NET）

- **SKIN-1 皮肤接入服务**：`app.UseReact(env)` 一行接入——注册嵌入式静态资源 + SPA 回退，提供完整管理后台前端。
- **SKIN-2 嵌入式静态资源**：`pnpm build` 产物 `wwwroot/` 由 csproj `<EmbeddedResource>` 嵌入 DLL，随 NuGet 分发，无物理文件依赖。
- **SKIN-3 SPA 回退路由**：未匹配任何 endpoint 的请求回退到 `index.html`，支持 React Browser History 路由刷新不 404。
- **SKIN-4 模块注册**：`ReactModule` 实现 `IModule`，`AddCube()` 自动发现；Module 模式仅注册静态文件。
- **SKIN-5 示例工程**：`CubeDemo` 演示引用皮肤包 + 实体控制器 + LOV 值集 + 文件存储 + Swagger 的完整用法（SQLite，免外部依赖）。
- **SKIN-6 NuGet 打包**：`NewLife.Cube.React` 包配置齐全（PackageId / 版本 / 图标 / 描述 / 符号包 snupkg）。

### 3.2 FND — 基础框架

- **FND-1 工程骨架**：Vite + React 19 + TypeScript + Ant Design 6 + Zustand + react-router；依赖 `@newlifex/*` 公共包；构建输出 `../wwwroot`。
- **FND-2 .NET 嵌入验证**：csproj 嵌入 wwwroot 编译通过；CubeDemo + `UseReact` 运行时全流程可用。
- **FND-3 配置系统**：`configure/`：defaultConfig + `window._CUBE_CONFIG_` 运行时覆盖。
- **FND-4 API 客户端**：`createCubeApi` 单例 + `onFieldError/onBusinessError/onUnauthorized` 统一提示与 401 跳转。
- **FND-5 用户/菜单 store**：登录态 + 菜单树↔扁平转换、激活、权限映射。
- **FND-6 路由与守卫**：静态路由表 + catch-all 动态实体页 + 登录守卫（未登录 → `/login?r=` 回跳）。
- **FND-7 布局系统**：RootLayout（登录态/菜单加载/多标签注入）+ MainLayout（Sider 动态菜单 / Header / Breadcrumb / Content / Footer）。
- **FND-8 多标签页**：多标签导航，首页固定标签，仅剩首页时隐藏标签栏。
- **FND-9 主题系统**：单一主题 × 明暗（antd token 驱动），明暗切换持久化。
- **FND-10 国际化**：语言清单来自后端（32 种，对齐 NewLife.Core `Localization.SupportedCultures`），可选语言 = **后端清单 ∩ 前端全量翻译语言**（11 种，所有 `t()` 文案键齐全）；其余语言保留增量词条用于强制语言与后续补齐，缺失词条回退英文；启动语言 `?lang=` → 本地存储 → 服务端文化 Cookie → 浏览器 → 英文，切换持久化并同步 antd 语言包、`<html lang/dir>`、`.AspNet.Culture` Cookie 与 URL `lang` 参数。请求携带 `Accept-Language`，后端按同一链路返回本地化消息。
- **FND-11 服务端本地化对接**：语言切换后刷新页面，重新拉取按请求语言返回的菜单、字段元数据与运行时消息；支持“跟随系统”与 `NewLife.Setting.Language` 强制语言（前端自动跟随）；语言代码归一化对齐 NewLife.Core（裸语言码、旧别名、区域映射、zh-Hans/zh-Hant）；`NewLife.Cube.React` 包内 `Locales/*.yml` 编译期生成词表，React 皮肤设置项与控制器文案随请求语言本地化。

### 3.3 AUTH — 认证登录

- **AUTH-1 登录页**：`/Cube/Site`（系统名/Logo/版权/背景/语言）+ `/Auth/LoginConfig`（密码/短信/邮箱能力、OAuth、注册开关）驱动；支持 `?tenant=` 租户标识；图片验证码 + RSA Challenge + MFA + OAuth 跳转 + 保存密码。
- **AUTH-2 注册页**：密码/手机/邮箱三方式 + OAuth 预填 + `RegisterAbility` 能力开关。
- **AUTH-3 激活页**：链接激活（token+account）+ 验证码激活 + 重发。
- **AUTH-4 忘记密码**：发送验证码 → 重置。
- **AUTH-5 安全中心**：MFA 状态/Setup/Activate(备用码)/Disable + 邮箱手机验证/更换。
- **AUTH-6 未授权/404 页**：`/unauthorized` + 404 友好页。
- **AUTH-7 保存密码（记住登录状态）**：登录携带 `remember=true` → 后端 JWT 延长至 365 天，可吊销（jti）。

### 3.4 LIST — 通用列表页

- **LIST-1 列表页骨架**：`createPageStore`（按 route 生成 type）+ `meta` 加载（setting/list/search/addForm/editForm/detail）+ 权限标志。
- **LIST-2 搜索栏**：动态搜索控件 + 搜索/重置回第 1 页。
- **LIST-3 工具栏**：新增/删除/导出/导入/图表/刷新 + 权限控制（canAdd/canDelete/canExport/canImport）。
- **LIST-4 表格**：动态列（链接/布尔/日期/数值/图片/LOV 翻译）+ 排序 + 行操作（编辑/删除）。
- **LIST-5 分页与统计**：页码/每页大小/总数 + 统计行 statData 展示。
- **LIST-6 导入导出**：导出 5 格式（axios blob 下载带 token）+ 导入（import 上传）。
- **LIST-7 图表弹窗**：`GET /{type}/charts` → ECharts 渲染（懒加载）。
- **LIST-8 批量删除**：多选 → `DELETE /{type}?ids=1,2,3`（≤100，前端分片）；条件删除 `DELETE /{type}?<搜索条件>`。
- **LIST-9 空/错误状态**：空数据友好提示、错误 message、页面不崩。

### 3.5 FORM — 通用表单页

- **FORM-1 扩展公共字段映射**：在 `@newlifex/field-mapping` 基础上扩展 lovCode/lovMulti、itemType（json/icon/singleselect/multipleselect/lovtable/markdown）、typeName（Enum/TimeSpan/Guid）、scale/precision。
- **FORM-2 fieldControl 映射**：`resolveControl/resolveSearchControl/resolveListControl` + `widgetToControl` + 全宽/精度判断。
- **FORM-3 表单控件渲染**：FieldControl 渲染器 + 各 AntD 控件（input/textarea/inputNumber/switch/datePicker/timePicker/lov/lovMulti/upload/image/json/richHtml/richMarkdown/color/icon/email/tel/url/readonly）。
- **FORM-4 提交序列化**：多选数组 → 逗号串（防后端 String 绑定报错）。
- **FORM-5 表单页模板**：add/edit 模式 + 详情加载（`GET /{type}/{id}`）+ 提交 `POST /{type}` 与 `PUT /{type}/{id}`（部分更新）+ 返回。
- **FORM-6 列表表单弹窗**：命令式 FormDialog（add/edit Modal + 成功后刷新列表）。
- **FORM-7 表单校验**：必填/格式校验（email/tel/url）+ 字段级错误提示。

### 3.6 CMP — 公共组件

- **CMP-1 LOV 选择**：LovSelect（ENUM/LIST）+ LovCell + useLovOptions + LovSelectTable 表格弹窗。
- **CMP-2 Uploader**：attachments API（新增/编辑带 id）+ 图片预览 + 文件链接。
- **CMP-3 富文本编辑器**：markdown 编辑 + marked+DOMPurify 渲染预览 / html 文本域。
- **CMP-4 JSON/颜色/图标**：JsonEditor + ColorPicker + IconSelector。
- **CMP-5 用户区组件**：UserMenu / UserAvatar / LogoutButton + NavbarSearch（菜单搜索）。
- **CMP-6 切换器**：ThemeSwitcher / LanguageSwitch / ModeSwitcher（明暗）。
- **CMP-7 通知铃铛**：NotificationBell（图标 + 未读角标 + 点击事件）。
- **CMP-8 AI 助手**：`POST /Ai/AiChat` SSE 流式 + 页面上下文 + mermaid 渲染 + 快捷指令 + `fill_form` 表单填充 + think 深度开关。
- **CMP-9 辅助组件**：ModalContainer + ActionButton + TextOverflow。
- **CMP-10 数据字典**：useLookup（`/Cube/Lookup` 批量字典）。

### 3.7 HOME — 首页

- **HOME-1 首页**：站点信息（`/Cube/Site` name/logo）+ 欢迎卡片 + 常用菜单（递归收集叶子）。
- **HOME-2 加载/过渡页**：`/loading` 加载页。
- **HOME-3 工作台数据接口**（后端）：`IndexController.Dashboard` 聚合端点 + `MonitorData` 监控端点。
- **HOME-4 工作台首页**：问候横幅、KPI 卡（点击跳转）、性能监控（5s 轮询）、快捷入口、常用菜单、个人信息、系统信息；接口不可用安全降级。

- **PKG-2 公共包回馈**：扩展 `field-mapping`（lov/json/icon/richHtml 等控件映射规则），补充 `page-logic` / `auth-logic` zustand 适配器能力，验证结果回流 monorepo 供 Vue 等共享。

### 3.9 CI — 工程与发布

- **CI-1 自动化测试**：web 构建 / 类型检查 / 单测 + .NET 解决方案构建流水线。
- **CI-2 NuGet 自动发布**：tag / 分支触发，web 前置构建后打包 `NewLife.Cube.React` 并发布。

### 3.10 META — 页面呈现架构适配

依据 `../NewLife.Cube/Doc/Api/页面呈现架构.md`（`/meta` 自描述契约），把后端声明的字段、视图与工具栏完整落到前端渲染，避免为单个字段复制整页组件。

- **META-1 元数据字段模型补齐**：字段元数据完整承接 `virtual`/`view`/`props`/`kind`/`end`/`field`/`visible`/`header`/`headerTitle`/`title`/`dataAction`/`textAlign`/`maxWidth`/`class`/`parentField`。
- **META-2 元数据装配**：`entity.primaryKey` 决定主键；`toolbar`/`ui` 进入页面状态；`list` 即全部可用列（`visible:false` 默认隐藏但可开启）。
- **META-3 能力与权限分离**：`setting` 只提供页面能力（`enableAdd`/`enableSelect`/`isReadOnly` 等）与动作所需权限位（`menuId`+`requiredPermissions`），有效权限由前端结合当前用户计算，系统管理员直通。
- **META-4 字段级全局渲染器**：后端下发 `view` 名与 `props`，前端按名注册组件，列表单元格、搜索控件、表单控件三处复用；未注册时降级默认控件。
- **META-5 页面呈现配置（preset）**：纯前端的呈现补丁（列宽/对齐/固定/表头/列序/隐藏/表单列数与分组/行按钮/条件显隐），合并顺序为 `meta → preset → 用户列偏好`，用户列偏好存 `localStorage`。
- **META-6 混合页扩展点**：区分 M1 动态页、M2 混合页、M3 自定义页；M2 提供自定义列渲染、搜索区替换、表单体替换、工具栏追加与行操作追加的对外入口。
- **META-7 ItemType 完整映射**：`percent`/`money`/`decimal(p,s)`/`file-zip` 等 `ItemType` 的格式化与控件映射补齐，映射表保持唯一入口。

> 由上述契约细化出的列表/表单补充项（查询项 `keyword`/`range`、列呈现属性、列偏好、工具栏自定义按钮、页面能力开关、链接占位符、表单分组与虚拟字段）见[功能清单](功能清单.md) LIST-11~17、FORM-9~10。

### 3.11 与魔方主线能力对齐（补充项）

对照魔方《需求文档》《功能清单》《架构设计》检查得出，以下为魔方已有、本皮肤尚缺的能力：

- **FND-15 语言链路对齐**：语言按 `?lang=` → `Accept-Language` → 租户默认 → 站点默认 → 英文解析；选择只存浏览器与请求头，**不写服务端 Cookie/用户参数**；固定语言由 `CubeSetting.LanguageLocked`、租户语言白名单由 `TenantSetting` 下发。
- **CMP-13 通知中心未读闭环**：铃铛接入未读数、最近未读、标记已读/全部已读与轮询（**依赖后端接口**：`NewLife.Cube` API 侧目前无通知端点）。
- **LIST-17 树形实体页**：菜单/部门/地区等树形实体按树展示（父子缩进、展开收起）。父字段自动识别，可用 `preset.treeBy` 覆盖或关闭。
- **LIST-18 树节点排序**（暂缓）：拖拽/上移下移节点排序，依赖后端排序接口与行操作扩展点，待实际需求出现再评估。

### 3.12 ITYPE — ItemType 呈现能力扩容

`ItemType` 是后端显式声明的「元素类型」（XCode `Model.xml` 的 `ItemType` 属性、`[BindColumn(ItemType = "...")]`），用于在 CLR 类型之外进一步指定呈现方式，例如 `image`、`money`、`TimeSpan:<格式>`。兜底的「按数据类型 + 长度 + 命名 + 备注习惯」推断只能覆盖常见情况，显式声明才是精确手段，因此本皮肤按魔方既有口径把 `ItemType` 尽量映射完整。

口径来源：CubeNC 视图（`_Form_Item`/`_Form_String`/`_Form_File`/`_List_Data_Item`/`_Common_List_Search` + `ViewHelper.FormatValue`）、Vue 皮肤（`core/utils/fieldControl.ts`、`core/components/CubeTable/cubeTable.logic.ts`）、XCode/Cube 生态实际出现的取值。

- **ITYPE-1 表单控件别名补全**：`email`/`phone`/`fax`/`secret`/`text`/`number`/`avatar`/`attachment`/`richtext` 等别名与无后缀 `area`（等价三级）归入唯一映射表；`timespan` 按数值输入编辑。
- **ITYPE-2 附件后缀 accept 推导**：`image-png`、`file-zip-doc` 等按 `-` 拆词推导上传 `accept`（对齐 MVC `_Form_File`）。
- **ITYPE-3 列表时长格式化**：`TimeSpan`/`TimeSpan:<格式>` 按描述单位（毫秒/秒/分/小时）换算后套默认或自定义格式。
- **ITYPE-4 列表 Unix 时间戳**：数值列上的 `Time`/`Time:<格式>` 视为 Unix 秒，转本地时间展示。
- **ITYPE-5 列表自定义日期格式**：日期时间列 `time-<格式>` 按声明格式输出。
- **ITYPE-6 列表容量格式化**：`GMK` 按 1024 进制输出 K/M/G…（附件大小等）。
- **ITYPE-7 列表附件前缀与显示别名**：`image-*`/`file-*` 前缀与 `avatar`/`attachment`/`richtext` 等别名按附件与富文本渲染。
- **ITYPE-8 搜索控件扩容**：`area`、附件前缀与 `dateRange` 在动态搜索区得到对应控件。
- **ITYPE-9 精度口径统一**：`percent` 未声明 `scale` 时按后端 `p{scale-2}` 口径输出 0 位小数。
- **ITYPE-10 测试字段实体全覆盖回归**：以 `CubeDemo/Areas/Test` 的「测试字段」实体（25 字段覆盖全部 ItemType）为验收对象，E2E 校验控件分派。

## 4. 🧊 暂缓清单

| 功能 | 暂缓理由 | 解冻前提 |
|------|----------|----------|
| npm 公共包发布 | 无 npm 发布权限；公共包处于快速演进期，Vue/React 双端频繁修改，发布节奏不划算 | 公共包 API 趋于稳定；取得 `@newlifex` scope 发布权 |
| GitHub Actions 自动化 | 依赖 npm 发布先落地；当前 `.github/workflows` 为旧仓库拷贝需整体改造 | npm 发布就绪后统一改造 test / publish / publish-beta |
| SelfHost 7081 一体化调试 | 独立仓库已裁剪该能力；CubeDemo(5050) 已覆盖开发调试 | 需要一体化调试场景（前后端同进程）时恢复 |

## 5. 不做什么

- 不把公共包源码复制进本仓库（会产生双份代码分叉，破坏"独立仓库共享公共包"的长期方向）
- 不引入 ProComponents 等重型组件库（antd 原生 + 自定义字段驱动组件即可）
- 不做完整 WYSIWYG 富文本编辑器（当前 markdown/html 轻量方案够用，需引入第三方库时再选型）
- 不承担后端业务功能（后端由 `NewLife.Cube` 核心库提供，本仓库只做皮肤接入与前端展示）
